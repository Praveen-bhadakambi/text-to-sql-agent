How it works

From question to result in 5 steps

Every query goes through a secure pipeline — no raw SQL is ever accepted from users.

1
User sends a plain English question
No SQL knowledge needed. The user types a question like "Which department has the highest budget?" via the REST API.
POST /query
2
Schema inspector reads all 6 tables
Dynamically reads the live database structure — table names, columns, types, and foreign key relationships — and builds a context string for the LLM.
schema_inspector.py
3
Groq LLaMA 3 generates the SQL
The question and schema are sent to Groq LLaMA 3. The model returns a raw SQL SELECT query with exact column names, correct JOINs, and proper syntax.
llm_service.py — Groq API
4
Safety validator blocks dangerous operations
Scans for 8 destructive keywords — DROP, DELETE, UPDATE, INSERT, TRUNCATE, ALTER, CREATE, PRAGMA. Any match is rejected with HTTP 400.
sql_validator.py
5
SQLite executes and returns JSON results
The safe SELECT query runs on SQLite. Results are saved to query history and returned as JSON — including the generated SQL for full transparency.
database.py — SQLite

Security

Built with safety first

Every query passes multiple security checks before touching the database.

🛡️
SQL injection prevention
Blocks 8 destructive SQL operations using regex pattern matching with comment stripping before execution.
⏱️
IP-based rate limiting
Enforces 5 requests per IP per day. Excess requests return HTTP 429 Too Many Requests.
✅
Read-only enforcement
Only SELECT queries are allowed. Any other operation is rejected before reaching the database.
🔍
Input validation
All requests validated via Pydantic v2. Empty, oversized, or malformed inputs are rejected before any LLM call.
